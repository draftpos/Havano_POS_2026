# Workspace Rules

- **Code Change Logging**: For every code modification, append a summary and description of the change (including timestamp, file paths, line numbers, and a brief description of the change) to a central Markdown file named `change_history.md` in the project root.
- **Strict Anti-Fallback Rule**: NEVER write code with fallback values for server hosts, API URLs, database connections, or SaaS endpoints. Never fall back to dummy/local servers like `http://localhost`, `http://localhost:8069`, `http://localhost:8000`, or localhost ports. If configuration is missing or invalid, require explicit configuration or raise an explicit error instead of falling back to localhost.
- **SaaS Mode Endpoint Standard**: SaaS mode always and exclusively targets `https://backoffice.havano.pro/`. Whenever configuring, defaulting, or pointing to the SaaS backend, use `https://backoffice.havano.pro/`. Never use `localhost` or any arbitrary local ports for SaaS endpoints.
- **Canonical File Paths Rule**: NEVER use hardcoded or relative file paths to access `app_data/` files. Never write `Path("app_data/...")`, `os.path.join("app_data", ...)`, `os.path.abspath(".")`, or `os.getcwd()` to build file paths. ALWAYS use `from database.db import get_app_data_dir` and then `get_app_data_dir() / "filename.json"`. This is the single canonical path resolver for all app_data files (sql_settings.json, hardware_settings.json, print_debug.log, etc.) and works correctly whether the app is launched via shortcut, auto-start, or terminal. Consult the `canonical-paths` skill before writing any file I/O code.
